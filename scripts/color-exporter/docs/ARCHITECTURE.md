# Устройство экспортёра

Один проход по каждому дереву палитры формирует активные токены. Затем общий алгоритм соединяет их с прежним JSON. Обе точки входа используют эти же функции.

Общая часть имени вычисляется один раз на секцию. Активные записи сортируются, затем к ним добавляются отсутствующие токены из уже отсортированного прежнего JSON — без отдельной коллекции и повторной сортировки устаревших.

| Модуль | Ответственность |
|---|---|
| [build.mjs](../build.mjs) | Очистка только `dist/color-exporter` перед сборкой TypeScript, чтобы удалённое правило не продолжало действовать |
| [contract.mts](../src/contract.mts) | Форматы путей, общие типы, проверка объектов и сортировка ключей |
| [layout.mts](../src/layout.mts) | Обнаружение страниц, выбор правил, проверка дерева, идентификаторы и пять итоговых полей |
| [color.mts](../src/color.mts) | Привязка к стилю или переменной, допустимая заливка, RGBA и HEX |
| [palettes/](../src/palettes/README.md) | Только отличия отдельных наборов |
| [sync.mts](../src/sync.mts) | Расчёт всех планов, сохранение и восстановление устаревших токенов |
| [files.mts](../src/files.mts) | Чтение обычных файлов, подготовка замен, проверка конкурентных изменений и откат |
| [transport.mts](../src/transport.mts) | Единственный запрос Figma REST с ограниченными повторами |
| [cli.mts](../src/cli.mts) | Параметры командной строки, сохранённый ответ REST, проверка без записи |
| [action.mts](../src/action.mts) | Основа из конкретного Git SHA, постоянная ветка, проверка индекса, отправка и запрос на слияние |

`prepare(source, loadBaseline, palette)` возвращает массив `Plan`: путь, прежний текст, рассчитанный текст и новые устаревшие ключи. Источник прежнего текста задаёт точка входа: локальный файл для командной строки или точный `context.sha` для GitHub Actions. Страницы обнаруживаются до чтения их JSON; отсутствующие страницы не запрашивают прежнее содержимое.

`writePlans(repoRoot, plans, compareBaseline)` записывает уже рассчитанные планы. При локальном запуске включено дополнительное сравнение с текстом, прочитанным для расчёта. В GitHub Actions прежний текст плана принадлежит основной ветке, поэтому для записи отдельно снимается состояние файлов служебной ветки.

Сеть, Git и файловая запись не участвуют в формулах имён и цветов. Правила формата и преобразования описаны в [FIGMA_FORMAT.md](FIGMA_FORMAT.md), порядок публикации — в [GITHUB_ACTIONS.md](GITHUB_ACTIONS.md).
