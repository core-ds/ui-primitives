# Подключение и отключение набора

Эта инструкция описывает только поведение экшена. Он получает уже готовый Figma-файл через REST, читает существующие узлы и синхронизирует JSON. Как страница и её раскладка создаются в Figma, в обязанности экшена не входит.

## Главное правило

Источником списка синхронизируемых наборов служат страницы Figma, а не список JSON в репозитории и не реестр исключений.

- есть страница с именем `colors_<название_набора>.json` — набор участвует в синхронизации;
- нет такой страницы — соответствующий JSON не синхронизируется;
- появился новый JSON в `styles`, но одноимённой страницы нет — экшен его игнорирует;
- появилась новая стандартная страница, но JSON ещё нет — экшен создаёт JSON сам;
- страница исчезла — экшен перестаёт синхронизировать набор и убирает только ожидающие изменения этого JSON, оставшиеся в служебной ветке от прошлых запусков.

Списка исключений нет. Любой JSON без одноимённой экспортной страницы просто не входит в запуск.

## Как имя страницы превращается в настройки

Для стандартной страницы всё вычисляется одной формулой.

| Вход | Результат |
|---|---|
| страница | `colors_new_palette.json` |
| идентификатор запуска | `new-palette` |
| целевой путь | `styles/colors_new_palette.json` |
| права нового файла | `0644` |
| исходное содержимое нового файла | пустой объект `{}` |

Допустимое имя страницы описано выражением `^colors_[a-z0-9_]+\.json$`: только строчные латинские буквы, цифры и подчёркивания после `colors_`. Регистр, пробелы, дефисы в машинной части и произвольные расширения не исправляются автоматически.

## Как добавить стандартный набор

Для набора, соответствующего общему контракту, в коде не нужно создавать модуль.

Особых модулей может не быть вообще. Командная строка обнаруживает стандартные страницы до применения `--palette`, поэтому `--palette new-palette` выбирает страницу `colors_new_palette.json` без отдельного исходного файла. Неизвестный идентификатор завершает запуск ошибкой.

1. В единственном файле [Color Exporter](https://www.figma.com/design/JGR9GpDXUneyYHfDdb7BDT/Color-Exporter) должна появиться готовая страница `colors_<название_набора>.json`.
2. Запустить экшен или локальную синхронизацию всех наборов.
3. Экшен найдёт страницу среди остальных страниц файла.
4. Если `styles/<имя страницы>` отсутствует в основной ветке, исходной версией считается `{}`.
5. Экшен разберёт страницу по стандартным правилам, создаст все токены и атомарно создаст JSON.
6. Новый JSON попадёт в обычную служебную ветку и в описание реквеста.

Никакого ручного перечня токенов нет. Любой новый фрейм с допустимым именем проходит тот же алгоритм, что первый токен набора.

## Стандартный контракт

Стандартная страница использует те же общие правила, что проверенная раскладка BlueTint:

- верхний уровень страницы: только `SECTION`;
- имя секции имеет вид `light/<путь>`, `dark/<путь>` или `static_<путь>`;
- внутренние `/`, `_` и `-` пути сохраняются; допустим конечный суффикс `_inverted`;
- режим переменной `light|dark` перед `/` и режим токена `static_` в имени переменной нельзя объединять;
- внутри секции: только `FRAME`;
- имя фрейма: строчные латинские буквы, цифры и дефисы;
- внутри фрейма: `RECTANGLE` с именами `default`, `hover`, `press` в этом порядке;
- разрешено любое непустое подмножество этих состояний;
- любое число прямоугольников с точным именем `empty` в любой позиции безусловно игнорируется, остальные свойства таких узлов не читаются;
- фрейм без настоящего цветового состояния запрещён.

Из секции, фрейма и состояния вычисляются JSON-ключ, `figma`, `web` и `alias`. Поля `rgba` и `hex` вычисляются из единственной заливки, которая обязана быть видимой, сплошной и связанной с переменной или цветовым стилем Figma. Полный расчёт всех полей описан в [`TOKEN_FIELDS.md`](TOKEN_FIELDS.md).

Общие фабрики также передают ядру режим в `PaletteIdentity.mode`; для стандартной страницы ничего дописывать не нужно. Если особый модуль полностью заменяет `deriveIdentity`, он обязан вернуть `key`, `figma` и непустой `mode`. Последнее поле задаёт область уникальности `figma` и `alias` и не записывается в JSON. Ядро всегда отклоняет два источника одного ключа или `web` и два источника одного `figma` или `alias` внутри режима.

## Когда нужен отдельный модуль

Отдельный файл `src/palettes/<id>.mts` нужен только тогда, когда входной контракт набора отличается от стандартного. Примеры реальных отличий:

- разрешено только состояние `default`;
- имя секции подчиняется более узкому правилу;
- допустимый состав состояний зависит от семьи или токена;
- имя фрейма имеет специальный формат.

Явный модуль имеет приоритет над автоматически созданными правилами при точном совпадении `pageName`. Поэтому существующие проверенные наборы могут сохранять свои строгие контракты, а новые стандартные страницы подключаются без изменений ядра.

Модуль обязан задавать уникальный `id`, описание, `pageName`, `targetJson`, порядок состояний и все проверки преобразования. Источник Figma модулем не задаётся: все наборы читаются только из постоянного Color Exporter. Общее ядро нельзя дополнять условиями вида `if (palette.id === ...)`.

## Как перейти со стандартных правил на особые

1. Оставить имя страницы и имя целевого JSON без изменений.
2. Добавить модуль `<id>.mts` с тем же `pageName`.
3. Описать только реальные отличия и покрыть их сценариями.
4. Проверить, что полный результат существующего JSON не изменился без причины.

На следующем запуске автоматическая фабрика увидит точное совпадение и не создаст второй набор. Дубли `id`, целевого пути или страницы останавливают запуск.

## Как отключить набор

Чтобы набор перестал синхронизироваться, его экспортная страница должна исчезнуть из Figma-файла. Дополнительное исключение в коде не добавляется.

Если экспортных страниц не осталось, общий запуск возвращает пустой список. Цветовые JSON при этом не читаются и не записываются.

Дальнейшее поведение зависит от состояния служебной ветки:

### JSON уже есть в основной ветке

Экшен оставляет основной JSON как есть. Если служебная ветка содержала ожидающее обновление этого файла от прошлого запуска, рабочая копия восстанавливается в точности из SHA основной ветки, создаётся согласующий коммит и выполняется обычная отправка ветки.

### JSON появился только в служебной ветке

Экшен удаляет его из служебной ветки, потому что в основной ветке такого файла ещё не было. Это очистка незавершённого добавления, а не удаление опубликованного производственного файла.

### Между ветками нет разницы

Экшен ничего не записывает, не коммитит и не отправляет. Наличие несинхронизируемого JSON в основной ветке само по себе не является ошибкой.

Если после согласования итоговое дерево служебной ветки совпало с основной, новый реквест не создаётся и существующий реквест не закрывается через API. Результат запуска сообщает, что старый реквест потерял актуальную разницу.

## Как вернуть страницу

Если страница с прежним именем появляется снова, она снова становится источником автоматически.

- существующий JSON основной ветки используется как исходная версия;
- активные токены пересоздаются из Figma;
- отсутствующие на странице ключи уходят в устаревший хвост;
- ранее устаревший ключ, вернувшийся на страницу, снова становится активным;
- отдельного действия «убрать из исключений» нет.

## Что происходит с токенами внутри активной страницы

Страница считается активной целиком, а каждый токен сравнивается отдельно.

- новый ключ добавляется как активный;
- существующий ключ полностью пересобирается из Figma;
- исчезнувший ключ сохраняется и получает `deprecated: true`;
- вернувшийся ключ полностью пересобирается и теряет `deprecated`;
- активные и устаревшие группы сортируются отдельно по одному стабильному алфавиту.

Исчезновение одного токена и исчезновение всей страницы — разные события. При исчезновении токена сохраняется история внутри JSON. При исчезновении страницы весь набор исключается из текущей синхронизации, а прежняя незавершённая разница служебной ветки убирается.

## Единственная область поиска

Экшен просматривает страницы только в Color Exporter с постоянным ключом `JGR9GpDXUneyYHfDdb7BDT`. Новая страница в этом файле подключается автоматически. Поддержки второго источника нет; модуль палитры не может её включить.

## Обязательные проверки после изменения правил

Команды выполняются из корня `ui-primitives`.

```bash
npm run typecheck
npm run test:colors
npm run test:colors:coverage
```

Для нового особого модуля также добавляются его отдельная русская инструкция, формульные проверки и данные полного обезличенного сценария. Для обычной стандартной страницы исходный модуль не создаётся; проверяется общий сценарий автоматического обнаружения.

## Запрещённые обходные решения

- добавлять список исключённых JSON;
- считать наличие JSON признаком подключения;
- создавать пустой JSON заранее только ради экшена;
- удалять опубликованный JSON основной ветки только из-за отсутствия страницы;
- угадывать имя страницы или исправлять его регистр;
- добавлять в модуль палитры другой Figma-файл;
- добавлять ручной перечень токенов;
- менять общий алгоритм ради одного особого набора;
- использовать ИИ или Figma MCP в рабочем экшене.
