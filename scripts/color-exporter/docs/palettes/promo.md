# Promo

## Источник и результат

- страница Figma: `colors_promo.json`;
- файл в коде: `styles/colors_promo.json`;
- модуль: `src/palettes/promo.mts`.

## Секции и состояния

Динамические секции используют режим переменной Figma `light` или `dark`, отделённый `/`, и семьи `promo`, `promo-muted`, `promo-pale`, `promo-vibrant`. После игнорирования всех `empty` каждый их фрейм содержит любое непустое подмножество `default`, `hover`, `press` в таком порядке.

В секции `static_promo` режим токена `static` записан в имени переменной. Для неё разрешён только настоящий `default`. `empty` можно повторять в любой позиции; его остальные свойства не читаются, сам узел не экспортируется.

## Алгоритм полей JSON

Promo полностью использует [стандартный алгоритм всех пяти полей](../TOKEN_FIELDS.md) без отличий. Особый модуль только разделяет динамический и статический состав настоящих состояний.

## Отсутствующие в Figma токены

В старом JSON есть цвета, которые прежде существовали только в коде и не имели опубликованной переменной Figma. Экспортёр не создаёт их из догадок и не удаляет: отсутствующий на странице ключ переносится в отсортированный хвост с `deprecated: true`. Если переменная позже появится на странице, токен снова будет полностью рассчитан и станет активным.

## Пример

```text
секция: light/promo-vibrant
фрейм: tomato
состояние: hover
```

```text
key   = light_promo_vibrant_tomato_hover
figma = promo-vibrant/tomato/hover
web   = --color-light-promo-vibrant-tomato-hover
alias = promoVibrantColorTomatoHover
```
