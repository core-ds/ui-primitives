# Формат экспортной страницы Figma

Этот документ описывает только вход, который читает экшен. Как дизайнер создаёт или выравнивает раскладку, в обязанности экшена не входит.

## Единственный источник

Экшен читает только файл [Color Exporter](https://www.figma.com/design/JGR9GpDXUneyYHfDdb7BDT/Color-Exporter) с постоянным ключом:

```text
JGR9GpDXUneyYHfDdb7BDT
```

Другие Figma-файлы не обнаруживаются, не настраиваются модулями палитр и не запрашиваются. За запуск выполняется один полный запрос `GET /v1/files/JGR9GpDXUneyYHfDdb7BDT`; все страницы читаются из одного ответа.

## Общая вложенность

```text
PAGE: имя целевого JSON
└── SECTION: режим и семья
    └── FRAME: имя токена
        ├── RECTANGLE: настоящее состояние или empty
        ├── RECTANGLE: настоящее состояние или empty
        └── RECTANGLE: настоящее состояние или empty
```

Количество прямоугольников заранее не фиксировано. Фрейм может содержать одно настоящее состояние без `empty`, одно настоящее состояние вместе с любым числом `empty` или несколько настоящих состояний с `empty` между ними. Для экшена это одно правило: сначала безусловно отбросить все прямоугольники с точным именем `empty`, затем обработать оставшиеся состояния.

Ядро не обходит произвольные вложенности. Допустима только глубина `CANVAS → SECTION → FRAME → RECTANGLE`. На странице не может быть других верхних узлов. Имя секции не повторяется на странице, имя фрейма — внутри секции, а имя настоящего состояния — внутри фрейма.

## Страницы и JSON

Имя экспортной страницы обязано иметь вид `colors_<название_набора>.json` и одновременно является именем целевого файла:

```text
страница colors_new_palette.json
→ styles/colors_new_palette.json
```

- страница есть — набор синхронизируется;
- JSON отсутствует — экшен создаёт его;
- страницы нет — одноимённый JSON не синхронизируется;
- две страницы с одинаковым именем — ошибка, экшен не выбирает одну из них.

Новая страница без особого модуля получает стандартный контракт: любое непустое подмножество `default`, `hover`, `press` в указанном порядке. Особый модуль может сузить имена и перечень настоящих состояний, но правило безусловного игнорирования `empty` остаётся общим. Отличия наборов находятся в [`palettes/README.md`](palettes/README.md), общий расчёт полей — в [`TOKEN_FIELDS.md`](TOKEN_FIELDS.md).

Отсутствие особых модулей допустимо. Если экспортных страниц нет, общий запуск возвращает пустой список и не читает и не записывает цветовые JSON.

## Имя секции и режим

Стандартное имя секции записывается одним из трёх способов:

```text
light/accent
dark/qualitative-duocolor/set-c
static_accent
```

В `light/<путь>` и `dark/<путь>` первый сегмент — режим переменной Figma. Он участвует в JSON-ключе и `web`, но не входит в `figma` и `alias`. Всё после первого `/` сохраняется как путь.

В `static_<путь>` слово `static` — режим токена, записанный в имени переменной. Полное имя секции участвует в ключе, `figma`, `web` и `alias`.

Одновременно указывать режим переменной и режим токена нельзя.

Суффикс `_inverted`, если он разрешён набором, относится к пути после режима переменной: `dark/accent_inverted`.

## Настоящие состояния

Стандартный порядок настоящих состояний:

1. `default`;
2. `hover`;
3. `press`.

Пропуск разрешённого состояния допустим. Повтор, неизвестное имя или перестановка настоящих состояний останавливают экспорт. Прямоугольники `empty` не влияют на проверку порядка: например, следующие два фрейма дают одинаковый результат:

```text
[default]
[empty, default, empty]
```

Фрейм обязан содержать хотя бы одно настоящее разрешённое состояние после удаления всех `empty`. Непустоту проверяет ядро; модуль палитры не может отменить это требование.

## Служебный прямоугольник `empty`

`empty` — только служебный прямоугольник раскладки. Он не обозначает отсутствующий `default`, `hover` или `press`; экшен не определяет его смысл и просто не экспортирует его.

Единственный признак — точное имя `empty`. После проверки общего типа узла `RECTANGLE` экшен сразу пропускает его и не читает размер, координаты, заливки, обводки, привязки или другие свойства. Модуль конкретного набора этот узел не получает и не может изменить правило.

Позиция и количество не ограничены. `empty` может стоять до, после или между настоящими состояниями. Фрейм только из `empty` запрещён, потому что после игнорирования не останется ни одного токена.

## Заливка настоящего состояния

У настоящего цветового прямоугольника должна быть ровно одна заливка всего. Она обязана:

- быть видимой: `visible` отсутствует или не равен `false`;
- иметь тип `SOLID`;
- быть связана с переменной или цветовым стилем Figma.

Допустимые признаки связи в ответе Figma REST:

- `rectangle.styles.fill` — цветовой стиль Figma;
- `rectangle.boundVariables.fills` — переменная заливки узла;
- `fill.boundVariables.color` — переменная цвета самой заливки.

Ручная заливка, для которой REST содержит только числовой `color`, запрещена. Числа `r`, `g`, `b`, `a` нужны для вычисления результата, но сами по себе не доказывают связь со стилем или переменной.

Скрытых заливок быть не должно. Любая вторая заливка — видимая или скрытая — останавливает экспорт. Градиент, изображение или отсутствие заливки также недопустимы.

Итоговая альфа вычисляется так:

```text
color.a × fill.opacity × rectangle.opacity
```

После этого она округляется до двух знаков. Полный алгоритм `rgba`, `hex`, `figma`, `web` и `alias` описан в [`TOKEN_FIELDS.md`](TOKEN_FIELDS.md).
