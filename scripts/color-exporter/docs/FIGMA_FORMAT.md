# Формат Figma и алгоритм преобразования

Источником служит полный ответ `GET /v1/files/JGR9GpDXUneyYHfDdb7BDT`. Обрабатываются только прямые страницы `document.children`, имена которых соответствуют `colors_[a-z0-9_]+.json`. Такая страница должна быть `CANVAS`; повтор имени запрещён. Остальные страницы не участвуют в экспорте. Файлы репозитория не определяют список страниц.

## Дерево

Для каждой экспортной страницы требуется непустая последовательность:

```text
CANVAS: colors_example.json
  SECTION: light/accent
    FRAME: primary
      RECTANGLE: default
      RECTANGLE: hover
      RECTANGLE: press
```

На каждом уровне принимается только указанный тип узла. Имена секций внутри страницы и фреймов внутри секции уникальны. Имена фреймов по общему правилу состоят из строчных латинских букв, цифр и дефисов.

Стандартные секции: `light/<семейство>`, `dark/<семейство>` или `static_<семейство>`. Семейство может содержать несколько сегментов через `/`; в сегменте допускаются строчные латинские буквы, цифры, `_` и `-`. После `light/` или `dark/` семейство не может начинаться с `static_`, `light_` или `dark_`. Особые ограничения перечислены в [карточках наборов](palettes/README.md).

Настоящие состояния идут в порядке `default` → `hover` → `press`, без повторов. Допускается любое непустое подмножество: например, только `hover` или `default` и `press`. Для отдельных наборов или фреймов разрешён только `default`.

Прямоугольник `empty` — заполнитель: он пропускается до чтения заливок, прозрачности и привязок. Заполнителей может быть несколько, в любых местах. Фрейм только из `empty` запрещён; хотя бы одно настоящее состояние обязательно.

## Цвет

У настоящего прямоугольника должна быть ровно одна заливка, с учётом скрытых. Её тип — `SOLID`, значение `visible` не равно `false`. Вторая скрытая заливка тоже делает данные недопустимыми.

Требуется хотя бы одна корректная связь с Figma:

- `rectangle.boundVariables.fills`: массив из одного `VARIABLE_ALIAS` с непустым `id`;
- `paint.boundVariables.color`: `VARIABLE_ALIAS` с непустым `id`;
- `rectangle.styles.fill`: непустой идентификатор стиля.

Если поле привязки присутствует, его формат проверяется даже при наличии другого корректного источника. Ручная заливка без связи не экспортируется. Числовой цвет берётся из `paint.color`, уже разрешённого REST API; отдельного поиска переменной или стиля нет.

`r`, `g`, `b` обязательны. Все каналы и коэффициенты прозрачности должны быть конечными числами от `0` до `1`; `null` недопустим. Отсутствующие `color.a`, `paint.opacity` и `rectangle.opacity` принимаются за `1`.

Расчёт:

```text
R = round(r × 255), G = round(g × 255), B = round(b × 255)
A = число из (color.a × paint.opacity × rectangle.opacity).toFixed(2)
rgba = "rgba(R, G, B, A)"
hex = #RRGGBB, если A = 1
hex = #AARRGGBB, иначе; AA = round(A × 255)
```

HEX записывается строчными буквами, каждый байт — двумя цифрами. Прозрачность в HEX находится в начале: это ARGB. Для RGB `239, 49, 36` и трёх коэффициентов по `0.5` получаются `rgba(239, 49, 36, 0.13)` и `#21ef3124`. Байты альфы рассчитываются из уже округлённого `A`.

## Идентификаторы и поля

Активный объект всегда содержит поля в порядке `rgba`, `hex`, `figma`, `web`, `alias`. Первые два вычисляются выше; остальные определяет положение прямоугольника.

Обозначения: `S` — имя секции, `F` — имя фрейма, `T` — настоящее состояние.

1. Для `light/...` и `dark/...` режимом является первый сегмент, а семейством — оставшаяся часть. Для статической секции всё имя является семейством.
2. Если всё имя `S` заканчивается на `_inverted`, этот суффикс временно убирается и возвращается после `F`. Иначе имя секции остаётся целиком. Ключ получается из секции, `_`, фрейма, перенесённого `_inverted` и суффикса состояния. У `default` суффикса нет; у остальных он равен `_hover` или `_press`. Затем все `/` и `-` заменяются на `_`.
3. `figma` равен `семейство/F`, с добавлением `/hover` или `/press`. Начальный режим `light/` или `dark/` исключается; статическая часть сохраняется. Внутренние слеши, дефисы, подчёркивания и `_inverted` сохраняются.
4. `web` равен `--color-` плюс JSON-ключ, в котором каждое `_` заменено на `-`.
5. Для `alias` семейство делится на сегменты по `/`. В конце любого сегмента может стоять `_inverted`; допускается не более одного такого сегмента. Суффикс удаляется из сегмента. В первом сегменте первое слово начинается со строчной буквы, следующие — с прописной; в остальных сегментах все слова начинаются с прописной. Границами слов служат `-` и `_`, разделители удаляются. Затем добавляются `Color`, имя фрейма со всеми словами с прописной буквы, `Inverted` при наличии суффикса и таким же образом состояние, если оно не `default`. Начальный режим `light` или `dark` в `alias` не входит, а слово `static` остаётся.

Полная схема ключа в одну строку:

```text
ключ = секция_без_конечного_inverted + "_" + фрейм + ("_inverted", если был) + ("_" + состояние, если не default); затем "/" и "-" → "_"
```

Если `_inverted` стоит у внутреннего сегмента, ключ сохраняет его внутри имени секции, а `alias` всё равно получает `Inverted` после имени фрейма. Имя фрейма `hover` само по себе не означает состояние: `light/accent` → фрейм `hover` → состояние `default` даёт `light_accent_hover` и `accentColorHover`.

| Секция / фрейм / состояние | Ключ | figma | alias |
|---|---|---|---|
| `light/accent` / `primary` / `default` | `light_accent_primary` | `accent/primary` | `accentColorPrimary` |
| `dark/accent_inverted` / `primary` / `hover` | `dark_accent_primary_inverted_hover` | `accent_inverted/primary/hover` | `accentColorPrimaryInvertedHover` |
| `static_accent_inverted` / `primary` / `press` | `static_accent_primary_inverted_press` | `static_accent_inverted/primary/press` | `staticAccentColorPrimaryInvertedPress` |
| `dark/qualitative-duocolor/set-c` / `1` / `default` | `dark_qualitative_duocolor_set_c_1` | `qualitative-duocolor/set-c/1` | `qualitativeDuocolorSetCColor1` |

Внутри одной страницы два источника одного `key` или `web` запрещены. Для `figma` и `alias` совпадения запрещены в пределах одного режима; одинаковые имена для `light` и `dark` допустимы. Совпадение самих цветов ошибкой не является.

## Сопоставление с прежним JSON

Сначала рассчитываются активные токены, затем читается прежний JSON этой страницы. Корень и значения токенов должны быть объектами. Ключи состоят из строчных букв, цифр и `_`; целочисленные ключи, которые JavaScript сам переставляет в начало объекта, запрещены.

Активный ключ полностью получает рассчитанные пять полей. Поэтому старый `deprecated` и произвольные дополнительные поля у возвращённого токена исчезают. Прежний ключ, отсутствующий в Figma, сохраняет свои поля и получает `deprecated: true` в конце объекта. Если он уже был устаревшим, его объект и порядок полей сохраняются.

Активные и устаревшие ключи сортируются отдельно по полному имени: `_` раньше цифр и букв, дальше — порядок символов без зависимости от языка системы. Сначала записываются активные токены, затем устаревший хвост. JSON использует табуляцию и один перевод строки в конце. Повтор с теми же данными даёт те же байты.

Все выбранные страницы должны успешно пройти расчёт до первой записи. Ошибка одной страницы прекращает запуск; пропущенная страница не создаёт пустую палитру и не требует чтения её прежнего JSON. Действия со служебной веткой при исчезновении страницы отдельно описаны в [GITHUB_ACTIONS.md](GITHUB_ACTIONS.md).
