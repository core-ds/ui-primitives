# Экспорт через GitHub Actions

[export-colors.yml](../../../.github/workflows/export-colors.yml) запускается вручную в `core-ds/ui-primitives` из основной ветки, указанной в `repository.default_branch`. Нужны секреты `FIGMA_TOKEN` и `GITHUB_TOKEN` с разрешениями `contents: write` и `pull-requests: write`. Одновременные запуски для репозитория выполняются последовательно.

Процесс получает полную историю, готовит Node.js 24, устанавливает зависимости, собирает и проверяет экспортёр. Затем запускает тот же алгоритм преобразования, что и локальная команда.

## Один запуск

До команд Git проверяются репозиторий, основная ветка, полный `context.sha`, секрет Figma и методы клиента GitHub. Автор коммитов — `github-actions[bot]`.

Постоянная служебная ветка — `feat/update-colors`. Её наличие проверяется через `git ls-remote --exit-code`; только код `2` означает отсутствие. Ошибки сети и авторизации останавливают запуск.

Если ветки нет, она создаётся от точного `context.sha`. Если есть, загружается её удалённое состояние, после чего в него обычным слиянием включается этот же SHA. Принудительная отправка не используется; конфликт слияния требует разбора.

Далее:

1. Загружается документ Figma и обнаруживаются страницы. Для каждой существующей страницы прежний JSON читается через `git show <context.sha>:<путь>`. Состояние служебной ветки не становится основой расчёта.
2. Все палитры рассчитываются и проверяются до записи. Незавершённые файлы исчезнувших страниц возвращаются к основной ветке: существовавшие восстанавливаются, созданные только в служебной ветке удаляются.
3. В индекс добавляются только активные палитры и восстановленные пути. Проверяются подготовленные изменения и вся разница индекса с точным SHA основной ветки, включая посторонние файлы из прежних коммитов. Нулевые разделители сохраняют точные имена, в том числе конечные пробелы.
4. Для активных JSON сравниваются ожидаемые и фактические записи индекса: путь, тип/права файла и стадия `0` — без неразрешённого конфликта. Список должен совпасть целиком: удаление, смена типа и изменение прав относительно основы запрещены; новый файл получает режим `100644`. Выполняется `git diff --cached --check`, сохраняется проверенное дерево индекса.
5. До коммита и отправки читается список открытых запросов на слияние из этой ветки в основную. Допускается не более одного запроса на слияние с корректным положительным номером.
6. Коммит создаётся только при изменениях в индексе относительно текущего коммита. Отправка выполняется после такого коммита или если слияние продвинуло ветку. Перед отправкой дерево коммита должно совпасть с проверенным деревом индекса; подмена хуком останавливает запуск.
7. Если итоговая ветка отличается от основы, запрос на слияние создаётся или обновляется. Описание содержит изменённые файлы, новые устаревшие ключи и ссылки на документацию. Автоматического слияния нет.

Проверка дерева относится к содержимому, которое будет отправлено. Незаписанное удаление постороннего файла из рабочей папки не скрывает его из индекса.

## Повторы до и после слияния

До слияния следующий запуск снова рассчитывает результат от основной ветки. При неизменных данных новый коммит и отправка не нужны, но существующий запрос на слияние обновляется.

Если отправка удалась, а создание запроса на слияние завершилось ошибкой, следующий запуск создаст запрос на слияние для уже отправленной разницы без нового коммита и без изменения SHA. После ошибки отправки повтор заново согласует ветку с её удалённым состоянием и повторит публикацию рассчитанного результата.

Когда основная ветка продвинулась, её точный SHA включается обычным слиянием. Отправка нужна и при пустом индексе, если это слияние изменило историю служебной ветки.

После слияния запроса на слияние новый запуск использует уже обновлённую основную ветку. Ветка `feat/update-colors` переиспользуется, если сохранилась, или создаётся заново, если её удалили.

При исчезновении страниц может понадобиться коммит восстановления и отправка, хотя итоговая разница с основой пуста. Тогда запрос на слияние не создаётся и не обновляется. Если открытый запрос на слияние ещё найден, журнал предлагает проверить и закрыть его вручную.

## Получение Figma REST

Используется один фиксированный адрес файла, встроенный `fetch` и тайм-аут `30` секунд на попытку. Перенаправления запрещены. Всего допускаются три попытки при сетевых сбоях и ответах `429`, `500`, `502`, `503`, `504`. Обычные задержки перед повторами — `500` и `1000` мс.

`Retry-After` учитывается как число секунд или дата. Если сервер требует ждать больше `30` секунд, запуск останавливается, не повторяя запрос раньше разрешённого срока. Некорректный JSON и остальные HTTP-ошибки не повторяются. Секрет передаётся только в заголовке и удаляется из текста ошибок.
