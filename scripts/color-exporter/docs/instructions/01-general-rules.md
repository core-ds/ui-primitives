# Как синхронизируются цвета

## Глоссарий

В схемах `[название]` обозначает подставляемую часть. Квадратные скобки не входят в имя. Всё вне скобок записывается буквально.

| Обозначение | Что означает | Конкретные примеры |
|---|---|---|
| `[набор]` | Отдельный экспортируемый набор цветов; определяет страницу и JSON-файл. | `bluetint`, `superapp`, `x5` |
| `[режим]` | Вариант цвета в экспорте: светлый, тёмный или статический. | `light`, `dark`, `static` |
| `[семейство]` | Группа токенов внутри набора. Может включать несколько частей пути. | `accent`, `superapp-component`, `qualitative-duocolor/set-a` |
| `[токен]` | Имя цвета внутри семейства; становится именем фрейма. | `primary`, `bg-secondary`, `1` |
| `[состояние]` | Основное значение, наведение или нажатие. | `default`, `hover`, `press` |
| `[inverted]` | Единственный необязательный модификатор: инверсия семейства. Подставляется `_inverted` или ничего. Это не режим и не состояние. | `accent_inverted` |
| `[секция]` | Полное имя секции: режим, семейство и `[inverted]`, если он есть. | `light/accent`, `dark/accent_inverted`, `static_brand` |
| `[ключ]` | Полный идентификатор записи в JSON. | `light_accent_primary_hover` |

**Страница** содержит один набор, **секция** — семейство в выбранном режиме, с `[inverted]` или без него, **фрейм** — токен, **образец** — прямоугольник его состояния. `empty` — пустой прямоугольник для выравнивания, не токен.

**Режим коллекции Figma** — отдельная настройка, которая выбирает значение переменной. Название секции задаёт имена в JSON. Цвета определяются режимом коллекции Figma, выбранным для этой секции. `static` — обозначение статических цветов в экспорте, а не требование иметь одноимённый режим коллекции.

## Страница и раскладка

Одна страница `colors_[набор].json` в Color Exporter соответствует файлу `styles/colors_[набор].json`. Новая экспортная страница подключается автоматически. JSON без своей страницы не участвует в экспорте.

Общая схема:

```text
Страница: colors_[набор].json
└── Секция: [секция]
    └── Фрейм: [токен]
        └── Прямоугольник: [состояние]
```

Только эти четыре уровня: страница → секция → фрейм → прямоугольник. Подписи, картинки и пояснения размещаются на неэкспортной странице, например `.gitignore`.

- `[секция]` = `[режим]/[семейство][inverted]` для `light`/`dark`; для статических цветов — `static_[семейство][inverted]`. Вложенные `/` в семействе остаются частью имени, без дополнительного контейнера.
- В `[токен]` используются строчные латинские буквы, цифры и дефисы; в `[семейство]` допустимы также подчёркивания и `/`.
- Образцы идут в порядке `default`, `hover`, `press`. Можно пропускать любые состояния, но хотя бы одно должно остаться.
- Экспортёр пропускает `empty`; отсутствующее состояние не появляется в JSON.

## Цвет и привязка

У каждого настоящего образца ровно одна видимая сплошная заливка, связанная с исходной переменной или стилем Figma. Ручной HEX и дополнительные заливки, даже скрытые, не подходят. Полностью прозрачный цвет с привязкой тоже является токеном.

Экспортёр проверяет наличие привязки, но не сверяет её имя и режим коллекции с именами слоёв. Это проверяется при подготовке раскладки.

## Что получается в JSON

Один настоящий прямоугольник — одна запись с полями `rgba`, `hex`, `figma`, `web`, `alias` в этом порядке.

Схема имени записи:

```text
[секция] → [токен] → [состояние]
                  ↓
                [ключ]
```

- **`[ключ]`:** `[секция]_[токен]_[состояние]`; `/` и `-` заменяются на `_`. Окончание `_default` не добавляется. `[inverted]` переносится за `[токен]`, перед состоянием.
- **`figma`:** `[семейство][inverted]/[токен]/[состояние]` для `light`/`dark`; `static_[семейство][inverted]/[токен]/[состояние]` для статических цветов. Исходные разделители сохраняются; `/default` не добавляется.
- **`web`:** `--color-[ключ]`, с дефисами вместо подчёркиваний в ключе.
- **`alias`:** `[семейство]` + `Color` + `[токен]` + `[inverted]` + `[состояние]`, без разделителей: первое слово со строчной, следующие с заглавной. При наличии `[inverted]` становится `Inverted`; `Default` не добавляется. Для статических цветов перед семейством сохраняется `static`.
- **`rgba` и `hex`:** текущий цвет с учётом прозрачности. RGB округляется до целых, итоговая прозрачность — до двух знаков. HEX записывается строчными буквами: `#rrggbb` или `#aarrggbb`, с прозрачностью в начале.

## Повторный экспорт

Найденные токены пересчитываются. Исчезнувшие сохраняются с `deprecated: true` (устарели); при возвращении пометка снимается. Сначала идут активные токены, затем устаревшие; каждый блок сортируется по полному ключу в порядке `_`, цифры, латинские буквы. Уже устаревшая запись при повторном отсутствии сохраняется без изменений.

Имена ключей и `web` уникальны внутри набора; `figma` и `alias` — внутри его режима. Совпадение цветов допустимо. Ошибка любой экспортной страницы останавливает расчёт до записи JSON. При одинаковых входных данных повторный экспорт даёт те же байты.

Особенности наборов — в [отдельном документе](02-bundle-exceptions.md); подготовка раскладок — в [инструкции для ИИ](03-ai-layout-guide.md).
