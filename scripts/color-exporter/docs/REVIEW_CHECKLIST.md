# Чек-лист ревью

## 1. Архитектура

- [ ] В ядре нет имён конкретной палитры.
- [ ] Новый стандартный набор подключается страницей `colors_<название_набора>.json` без правки ядра и без исходного модуля, даже при пустом каталоге особых модулей.
- [ ] `--palette` может выбрать новую стандартную страницу после её обнаружения; соседние JSON не записываются.
- [ ] JSON без одноимённой страницы не синхронизируется и не требует исключения.
- [ ] Новая стандартная страница создаёт отсутствующий JSON с правами `0644`.
- [ ] Экшен читает только Color Exporter `JGR9GpDXUneyYHfDdb7BDT`; модуль палитры не может выбрать другой файл.
- [ ] Явный модуль имеет приоритет только при точном совпадении `pageName`.
- [ ] Исчезновение страницы убирает только прежнюю ожидающую разницу служебной ветки, но не отменяет текущую синхронизацию и не удаляет опубликованный JSON основной ветки.
- [ ] Все палитры проверяются до первой записи.
- [ ] Наборы с одним `default` описаны фабрикой, а особые состояния остаются в модуле набора.
- [ ] Общее ядро не содержит условий по `palette.id`.
- [ ] Исходники и проверки проходят строгий TypeScript целевого репозитория без `@ts-nocheck`.

## 2. Figma

- [ ] Описана точная вложенность узлов.
- [ ] Нейминг проверяется, а не исправляется догадками.
- [ ] Режим переменной записан как `light/<путь>` или `dark/<путь>`, режим токена — как `static_<путь>`; одновременно они не используются.
- [ ] Внутренние `/`, `_` и `-` пути не перекодируются.
- [ ] Любой прямоугольник с точным именем `empty` безусловно игнорируется; его остальные свойства не читаются.
- [ ] Позиция и количество `empty` не влияют на результат и не сопоставляются с состояниями.
- [ ] Обработка `empty` находится в общем парсере и отсутствует в контракте модуля палитры.
- [ ] Содержательный прямоугольник имеет ровно одну заливку всего: видимую, `SOLID` и связанную с переменной или цветовым стилем Figma.
- [ ] Ручная заливка и любая дополнительная скрытая заливка останавливают экспорт.
- [ ] Дубли страниц, секций, фреймов и состояний останавливают экспорт.
- [ ] Фрейм из одной `empty` без цветового состояния запрещён.

## 3. Поля токена

- [ ] Порядок всегда `rgba`, `hex`, `figma`, `web`, `alias`.
- [ ] Все пять значений вычисляются при каждом запуске.
- [ ] Новый токен проходит тот же путь, что существующий.
- [ ] Формулы `web` и `alias` доказаны тестами на текущем наборе.
- [ ] `deriveIdentity` возвращает непустой `mode` по правилам набора; режим не угадывается по ключу и не попадает в JSON.
- [ ] Два источника одного ключа или `web`, а также одного `figma` или `alias` внутри режима останавливают весь экспорт с указанием обоих источников. Одинаковые цвета и ожидаемые совпадения между `light` и `dark` допустимы.
- [ ] У каждой палитры с особыми правилами есть отдельный модуль и отдельная русская инструкция.
- [ ] Каждая инструкция набора содержит полный алгоритм полей или явную ссылку на общий алгоритм с перечислением отличий.

## 4. Устаревшие токены

- [ ] Исчезнувший ключ не удаляется.
- [ ] У нового исчезнувшего токена `deprecated: true` стоит последним полем.
- [ ] Старые исторические `deprecated`-объекты не перестраиваются без источника Figma.
- [ ] Активная группа отсортирована отдельно.
- [ ] Устаревшая группа находится в конце и тоже отсортирована.
- [ ] Обе группы используют один явный алфавит без `localeCompare` и исключений палитр.
- [ ] Возвращённый токен снова полностью генерируется и теряет `deprecated`.

## 5. Безопасность

- [ ] Настоящего `FIGMA_TOKEN` нет в файлах и выводе.
- [ ] Токен Figma передаётся только заголовком, а временные сетевые ошибки повторяются ограниченно.
- [ ] Один тайм-аут охватывает получение заголовков и чтение JSON-тела.
- [ ] `Retry-After` до 30 секунд соблюдается точно; более длительное ожидание останавливает запуск без преждевременного запроса.
- [ ] Запрос с секретом не следует перенаправлениям; ошибочный ответ отменяется до повтора.
- [ ] `targetJson` не может выйти из `repo-root`.
- [ ] Проверяются реальные узлы целевого пути; ссылки вместо папок или JSON запрещены.
- [ ] Перед заменой повторно сверяются исходный текст и права; рабочая папка изолирована от параллельного редактирования.
- [ ] Подготовка всех временных файлов завершается до очистки, даже если одна запись упала.
- [ ] При неудачном восстановлении исходная копия сохраняется, её путь виден в сообщении; ошибки очистки не скрываются.
- [ ] Записываются только JSON активных страниц и пути, согласуемые из-за исчезнувших страниц.
- [ ] Отсутствующий JSON создаётся без перезаписи файла, появившегося параллельно.
- [ ] В Git-индексе нет посторонних файлов.
- [ ] В полной разнице итогового индекса с `context.sha` нет посторонних файлов из старых коммитов; имена не обрезаются по пробелам.
- [ ] Каждый изменённый файл соответствует результату синхронизации, а типы и права допустимы.
- [ ] Номер реквеста и его описание проверены до коммита; перед отправкой дерево коммита совпадает с проверенным индексом.
- [ ] Отчёт считается от JSON основной ветки, а не от уже изменённой служебной ветки.
- [ ] Внешние GitHub Actions закреплены по полным SHA, а кеш пакетов отключён.
- [ ] Одновременные ручные запуски ставятся в очередь, а не отменяют друг друга.
- [ ] Код независимо от условия задания разрешает запуск только в `core-ds/ui-primitives`, из основной ветки и с полным SHA.
- [ ] Используется обычная команда `push`; принудительная перезапись ветки запрещена тестом.
- [ ] Автоматического слияния нет.
- [ ] Описание реквеста перечисляет все ключи, впервые получившие `deprecated: true`.
- [ ] Повторный запуск после успешного `push` и ошибки GitHub API восстанавливает реквест без лишнего коммита.
- [ ] Пустая итоговая разница не закрывает старый реквест автоматически, а явно возвращает `stalePullRequest: true`.
- [ ] Согласование последней исчезнувшей страницы коммитится и отправляется без создания нового реквеста, в том числе при удалении нового JSON.
- [ ] Коммит обновления основы отправляется и без новых изменений в индексе.

## 6. Язык и понятность

- [ ] Поясняющие комментарии написаны по-русски.
- [ ] Описание реквеста написано по-русски.
- [ ] Комментарий объясняет причину, а не повторяет очевидную строку.
- [ ] Каждая сложная формула имеет пример.
- [ ] Тест можно прочитать как небольшой сценарий поведения.

## 7. Команды проверки

Команды выполняются из корня `ui-primitives`.

```bash
npm run typecheck
```

```bash
npm run test:colors
```

```bash
npm run test:colors:coverage
```

```bash
npm run sync:colors -- \
  --repo-root "/путь/к/ui-primitives" \
  --check
```

После реальной синхронизации повторный запуск в режиме `--check` должен завершиться с кодом `0`.

## 8. Полный слепок

- [ ] `tests/fixtures/full` содержит десять ожидаемых JSON и один обезличенный Figma-файл.
- [ ] В слепке нет идентификаторов узлов, пользователей, ссылок, истории и секретов.
- [ ] Полный сценарий проходит без пропуска и подтверждает 2057 активных и 232 устаревших токена.
- [ ] Отдельные сценарии доказывают одинаковый экспорт с `empty` в разных позициях и без него.
- [ ] Временные Git-репозитории реально проверяют восстановление реквеста, посторонний путь и согласование исчезнувшей страницы.
- [ ] Неправильный новый слепок не заменяет предыдущий; сначала проверяется временная копия.
