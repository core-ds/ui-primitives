# Алгоритм синхронизации

Ниже описан полный путь данных. В нём нет решений «по смыслу»: одинаковый вход всегда даёт одинаковый текст JSON и одинаковое описание реквеста.

## 1. Обнаружить особые модули

1. Собрать исходные `src/palettes/*.mts` в исполняемые `.mjs`.
2. Прочитать собранный каталог палитр и взять обычные `.mjs`, имя которых не начинается с `_`.
3. Отсортировать имена по кодовым единицам, без системной локали.
4. Импортировать каждый файл и проверить его контракт.

Исходный файл обязан быть `<id>.mts`, а собранный — `<id>.mjs`. Имя страницы Figma обязано совпадать с именем целевого JSON вида `colors_<название_набора>.json`, где название набора содержит строчные латинские буквы, цифры и подчёркивания. Повторы `id`, JSON или страницы запрещены.

Это не реестр всех наборов. Модули задают только проверенные особые контракты страниц. Новые стандартные страницы обнаруживаются позже в единственном Color Exporter. Каталог `styles` не сканируется как список заданий, явных исключений нет.

Каталог особых модулей может быть пустым. Набор полей определения модуля проверяется без требования к их порядку; порядок полей выходного токена проверяется отдельно.

## 2. Получить Figma-файл

В рабочем процессе выполняется ровно один запрос к единственному разрешённому файлу Color Exporter:

```text
GET https://api.figma.com/v1/files/JGR9GpDXUneyYHfDdb7BDT
X-FIGMA-TOKEN: <секрет>
```

Ключ файла зафиксирован в ядре. Модули наборов не могут указать другой источник, а экшен не ищет другие файлы в аккаунте.

Токен передаётся только заголовком. Одна попытка ограничена 30 секундами вместе с чтением JSON-тела. Даже если сетевая реализация проигнорировала отмену, отдельный таймер завершит попытку по тайм-ауту.

Сетевая ошибка, обрыв чтения тела и ответы `429`, `500`, `502`, `503`, `504` повторяются не более трёх раз. Базовые задержки — 500 и 1000 миллисекунд. Заголовок `Retry-After` до 30 секунд соблюдается точно. Если он требует ждать дольше, запуск останавливается с понятной причиной и не отправляет запрос раньше разрешённого времени. Синтаксически неправильный JSON и постоянные HTTP-ошибки не повторяются.

При локальной проверке вместо сети можно передать сохранённый полный ответ этого запроса. Один такой снимок содержит все экспортные страницы файла и подходит для проверки всех наборов.

## 3. Определить активные страницы

Из полного ответа выбираются все страницы, подходящие `^colors_[a-z0-9_]+\.json$`. Имена стабильно сортируются, дубли запрещены.

- При точном совпадении `pageName` используются правила явного модуля.
- Для остальных страниц стандартное определение создаётся в памяти: `colors_new_palette.json` превращается в `id = new-palette` и цель `styles/colors_new_palette.json`.
- Явный модуль, чья страница отсутствует, пропускается без ошибки и не читает свой JSON.

После объединения явных и стандартных определений повторы `id` и целевых путей запрещены.

Параметр локального запуска `--palette <id>` выбирает набор после обнаружения стандартных страниц. Поэтому он работает и с новым набором без собственного модуля. Неизвестный идентификатор считается ошибкой. Если экспортных страниц нет, общий запуск возвращает пустой список и не читает и не записывает цветовые JSON.

## 4. Проверить дерево

Допустима только такая глубина:

```text
CANVAS → SECTION → FRAME → RECTANGLE
```

Каждый узел обязан иметь ожидаемый тип, непустое имя и хотя бы одного ребёнка там, где дети обязательны. Имена секций не могут повторяться на странице, имена фреймов — внутри секции, имена состояний — внутри фрейма.

## 5. Обработать состояния и заглушки

Состояния проверяются в порядке, объявленном модулем палитры. Неизвестное, повторённое или переставленное состояние останавливает запуск.

Каждый прямоугольник с точным именем `empty` сразу игнорируется. Экшен не читает его размер, заливки, обводки, привязки или другие свойства. Позиция и количество не имеют смысла для экспорта; узел не сопоставляется с `default`, `hover` или `press`. После удаления всех `empty` во фрейме должно остаться хотя бы одно настоящее состояние, разрешённое модулем набора.

Непустоту проверяет само ядро перед проверкой состава фрейма модулем. Особые правила не могут разрешить фрейм только из `empty`.

Таким образом, `[default]` и `[empty, default, empty]` обрабатываются одинаково. Неизвестное, повторённое или переставленное настоящее состояние по-прежнему останавливает запуск.

## 6. Построить идентификатор

Для каждого настоящего состояния модуль возвращает три внутренних поля:

```js
{
    key: 'dark_accent_primary_inverted',
    figma: 'accent_inverted/primary',
    mode: 'dark',
}
```

Общее правило разбирает `light/` и `dark/` как режимы переменной Figma: режим остаётся в `key`, но не попадает в `figma`. Режим токена `static_` уже записан в имени переменной и остаётся в обоих полях. Одновременно использовать обе формы нельзя. Внутренние `/`, `_` и `-` не перекодируются туда и обратно.

`mode` — область проверки имён, которую явно определяет модуль палитры: `light`, `dark` или `static` в текущих наборах. Это непустая строка внутреннего контракта, не шестое поле JSON и не запрос к Variables API. Ядро не пытается восстановить режим из готового ключа. Особый модуль обязан вернуть область имён по правилам своего набора.

`key` может содержать только `a-z`, `0-9` и `_`. Повтор вычисленного ключа запрещён. Целочисленные ключи-индексы JavaScript от `"0"` до `"4294967294"` без ведущих нулей также запрещены: иначе сериализация сама переставит их перед остальными ключами. Это ограничение проверяется и для исторических токенов.

## 7. Прочитать цвет

У прямоугольника должна быть ровно одна заливка всего. Она должна быть видимой, иметь тип `SOLID` и быть связана с переменной или цветовым стилем Figma. Допустимы признаки REST `styles.fill`, `boundVariables.fills` или `fill.boundVariables.color`.

Ручная заливка без привязки запрещена. Скрытые заливки не игнорируются: любая дополнительная заливка, даже скрытая, считается ошибкой. Числовой цвет из REST используется только после проверки привязки.

Каналы Figma умножаются на 255 и округляются до целого. Итоговая альфа равна:

```text
color.a × fill.opacity × rectangle.opacity
```

Альфа округляется до двух знаков. Непрозрачный `hex` содержит шесть цифр, прозрачный — восемь цифр в порядке `AARRGGBB`.

## 8. Полностью создать активный токен

Старый объект не дополняется частями. Модуль заново создаёт ровно пять непустых строковых полей в фиксированном порядке:

```text
rgba → hex → figma → web → alias
```

Поэтому новый, существующий и вернувшийся из устаревших токен проходят одну формулу. Полный расчёт каждого поля приведён в [`TOKEN_FIELDS.md`](TOKEN_FIELDS.md).

Перед добавлением записи `token-sources.mts` проверяет результат преобразования: ключ и `web` должны иметь один источник на всю палитру; `figma` и `alias` — один источник внутри `mode`. Две версии одного имени в `light` и `dark` допустимы. Равные `rgba` и `hex` не проверяются на уникальность.

При совпадении экспорт останавливается. Ошибка содержит поле, совпавшее имя, оба исходных пути «страница → секция → фрейм → состояние», оба ключа и идентификаторы узлов, если они присутствуют в ответе Figma. Проверка не зависит от наличия старого JSON; исторические устаревшие токены не являются источниками текущей раскладки. Пока все страницы не пройдут проверку, ни один рассчитанный JSON не записывается.

## 9. Вычислить изменения

Для отчёта создаются четыре отсортированных списка:

- `newTokenKeys` — ключа раньше не было;
- `restoredTokenKeys` — старый объект имел `deprecated: true`, а теперь снова найден в Figma;
- `changedActiveTokenKeys` — прежний активный объект отличается от заново созданного;
- `newlyDeprecatedTokenKeys` — активный старый ключ исчез из Figma.

Списки содержат машинные ключи, а не свободный текст. Один ключ не может попасть в два вида изменений. Числа в `summary` обязаны совпадать с длинами этих списков.

## 10. Обработать исчезнувшие токены

Если старого активного ключа больше нет в Figma:

1. сохранить все его исторические поля и значения;
2. удалить старое поле `deprecated`, где бы оно ни стояло;
3. добавить `deprecated: true` последним полем.

Если объект уже был устаревшим, его поля не переставляются. Источник Figma для него отсутствует, поэтому пересчитывать исторический объект нельзя.

## 11. Отсортировать результат

Активная и устаревшая группы сортируются раздельно по полному JSON-ключу. Затем группы соединяются:

```text
result = sort(active) + sort(deprecated)
```

Алфавит задан прямо в `stable-order.mts`:

```text
_0123456789abcdefghijklmnopqrstuvwxyz
```

Сортировка не использует `localeCompare` и не допускает исключений отдельных палитр. Поэтому Monochrome, X5 и остальные наборы подчиняются одному правилу на любой машине.

## 12. Выбрать правильную исходную версию JSON

Локальная команда сравнивает Figma с текущим файлом.

GitHub Actions отдельно проверяет и читает каждый активный JSON из точного `context.sha`. Эта версия используется для списка изменений и описания реквеста. Если пути в основной ветке нет, исходной палитрой считается пустой объект. Текст рабочей служебной ветки используется только для ответа на вопрос «нужно ли сейчас переписать файл».

Чтение выполняется лениво после обнаружения страницы. JSON без страницы не читается.

Разделение позволяет восстановить реквест после прошлого успешного `push`: служебная ветка уже готова, но отчёт всё равно строится относительно основной ветки.

## 13. Подготовить все файлы

Каждый существующий рабочий JSON читается вместе с исходным текстом и правами доступа. Для отсутствующего файла выбираются права `0644`. Новый текст всегда сериализуется табами и заканчивается одним переводом строки.

Сначала все палитры полностью читаются, проверяются и вычисляются в памяти. Ошибка одной палитры не разрешает запись ни одной другой.

## 14. Безопасно заменить JSON

Для изменённых файлов алгоритм:

1. сверяет исходный текст и права либо отсутствие нового пути;
2. полностью готовит временные файлы с новым текстом и исходные копии;
3. повторяет проверку непосредственно перед каждой установкой;
4. заменяет существующие цели через `rename`, а новые создаёт через `link` без перезаписи;
5. при перехваченной ошибке восстанавливает только всё ещё принадлежащие запуску версии;
6. удаляет временные файлы; если восстановление не удалось, оставляет исходную копию и сообщает её путь.

Это не общая транзакция файловой системы. Условия изоляции, обработка ошибок и пределы гарантии описаны в [`FILE_WRITES.md`](FILE_WRITES.md).

Режим `--check` выполняет все вычисления, но пропускает запись. Код завершения `2` означает, что изменения найдены.

## 15. Согласовать служебную ветку с текущими страницами и проверить Git целиком

После записи активных страниц GitHub Actions проверяет остаток постоянной служебной ветки от предыдущих запусков. Если в ней осталась ожидающая разница JSON страницы, которой теперь нет, существующий в основной ветке путь восстанавливается из `context.sha`, а путь, добавленный только в служебной ветке, удаляется из неё.

Это не отменяет результат текущей синхронизации. Шаг убирает только старые ожидающие изменения исчезнувших страниц; на новой чистой ветке он ничего не делает.

Затем в индекс добавляются только JSON активных страниц и согласуемые пути исчезнувших страниц. После этого всё итоговое дерево сравнивается с `context.sha`. Посторонний путь запрещён независимо от того, попал он в текущий индекс или остался от старого коммита служебной ветки.

Список открытых реквестов читается даже при пустом индексе. Дальше:

1. если итоговой разницы и индекса нет — не менять внешнее состояние и сообщить об устаревшем открытом реквесте, если он есть;
2. если есть индекс — создать коммит и выполнить обычный `push`, включая согласование последней исчезнувшей страницы;
3. если индекс пуст, но ветка отличается — пропустить коммит и `push` как уже выполненные прошлым запуском;
4. детерминированно построить русское описание;
5. создать реквест или обновить существующий.

Автоматического слияния нет.

## Сокращённый псевдокод

```text
specialPalettes = discoverAndValidateModules()
figmaFile = fetchColorExporterOnce("JGR9GpDXUneyYHfDdb7BDT")
pages = listColorJsonPages(figmaFile)
palettes = preferSpecialRulesOrCreateStandardRules(pages, specialPalettes)

prepared = palettes.map(palette => {
    baseline = readJsonFromMainShaOrEmptyObject(palette.targetJson)
    rectangles = parseStrictLayout(figmaFile)
    active = rectangles.withoutPlaceholders().map(palette.makeToken)
    deprecated = baseline.minus(active.keys).markDeprecated()
    return sort(active) + sort(deprecated)
})

if every prepared item is valid:
    verifyTargetsDidNotChange()
    replaceChangedFiles()
    restoreBranchFilesWhosePagesDisappeared()
    verifyWholeBranchAgainstMainSha()
    createOrRecoverPullRequestWithoutAutoMerge()
```
