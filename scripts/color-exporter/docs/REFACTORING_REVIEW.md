# Разбор рефакторинга — 5 сентября 2026

Основные разделы фиксируют работу над самостоятельным драфтом. Результаты последующего переноса в репозиторий приведены в конце документа.

## Итог

Исправлены ошибки в обнаружении наборов, проверке данных, записи файлов и подготовке ветки. Правила получения текущих цветов не менялись: полный проверочный слепок десяти палитр воспроизводится побайтно. Новых зависимостей нет.

Работа выполнена в самостоятельном драфте. Производственные JSON, раскладки палитр Figma и внешние реквесты не изменялись. Инструкция синхронизирована с кодом. Перенос и публикация экшена остаются отдельным шагом.

## Что исправлено в поведении

### 1. Проверки публикации выполняются до отправки

**Было:** при непустом индексе экшен мог создать коммит и отправить ветку, а затем обнаружить, что синхронизатор вообще не подтвердил изменения. Проверки хотя бы одного изменённого набора также было недостаточно для нескольких JSON.

**Стало:** каждый путь разницы итогового индекса сопоставляется с результатом своего набора. Список открытых реквестов, номер существующего реквеста и описание проверяются заранее. После коммита его дерево сверяется с уже проверенным деревом индекса — изменение подготовленных файлов обработчиком коммита запрещает отправку.

**Почему:** ошибка должна предотвращать публикацию, а не объяснять уже отправленную неправильную ветку.

Код: [`publication-plan.mts`](../src/action/publication-plan.mts), [`run-github-action.mts`](../src/action/run-github-action.mts). Проверки: [`action.test.mts`](../tests/action.test.mts), [`git-integration.test.mts`](../tests/git-integration.test.mts).

### 2. Проверяется именно то дерево Git, которое будет отправлено

**Было:** обрезка пробелов в выводе Git могла превратить постороннее имя `colors_example.json ` в разрешённое `colors_example.json`. Сравнение рабочего дерева вместо индекса позволяло незаписанной правке скрыть посторонний файл из проверки. Тип и права файла отдельно не проверялись.

**Стало:** имена читаются с нулевым разделителем без изменения символов. Проверяется итоговый индекс, включая всю его разницу с основной веткой. Символические ссылки, подмодули и смена режима файла запрещены; новый JSON должен быть обычным неисполняемым файлом.

**Почему:** список похожих имён — не доказательство безопасности будущего коммита.

Код: [`git-operations.mts`](../src/action/git-operations.mts). Регрессии воспроизведены настоящим Git, без обращения к GitHub.

### 3. Исправлены два сценария продолжения служебной ветки

- Исчезновение страницы нового, ещё не принятого JSON больше не приводит к ошибке `pathspec`: уже подготовленное удаление не передаётся повторно в `git add`.
- Коммит обновления основы отправляется и тогда, когда после синхронизации новых изменений в индексе нет. Локальная история не расходится молча с удалённой.

Кроме того, если итоговая разница исчезла, журнал сообщает номер оставшегося открытого реквеста и необходимость проверить его вручную. Автоматического закрытия или слияния не добавлено.

### 4. Запуск стандартных наборов больше не зависит от особых модулей

**Было:** два независимых запрета пустого списка модулей мешали работать только со стандартными страницами. `--palette` искал набор до чтения Figma и не мог выбрать новую стандартную страницу.

**Стало:** наборы обнаруживаются по страницам, затем применяется выбор команды. Пустой каталог особых правил допустим. Отсутствие всех экспортных страниц возвращает пустой результат без записи; неизвестный явно запрошенный идентификатор по-прежнему считается ошибкой.

**Почему:** новый стандартный набор должен добавляться страницей, а не обязательным исходным файлом или записью в реестре.

Код: [`discover-palettes.mts`](../src/core/discover-palettes.mts), [`run-palettes.mts`](../src/core/run-palettes.mts), [`cli.mts`](../src/cli.mts). Проверки включают выбор новой страницы и отсутствие записи соседних JSON.

### 5. Усилены проверки данных без изменения формул текущих токенов

- Фрейм из одних `empty` отклоняется самим ядром: особый модуль не может случайно снять общее требование настоящего состояния.
- Явный `null` в коэффициенте прозрачности не считается отсутствующим значением и больше не подменяется единицей.
- Состояние передаётся в формулу `alias` явно. Угадывание по последнему сегменту пути убрано: фрейм с именем `hover` сам по себе не означает состояние `hover`.
- Ключи-индексы JavaScript — целые числа `0`…`4294967294` без ведущих нулей — отклоняются. Иначе движок ставил бы такой ключ перед активными токенами независимо от сортировки. Стандартные формулы создают ключи с префиксом; текущие палитры ограничение не затрагивает.

Проверки: [`bluetint.test.mts`](../tests/bluetint.test.mts), [`format-color.test.mts`](../tests/format-color.test.mts), [`palette-factory.test.mts`](../tests/palette-factory.test.mts), [`stable-order.test.mts`](../tests/stable-order.test.mts), [`sync-palette.test.mts`](../tests/sync-palette.test.mts).

### 6. Запись файлов разделена на проверяемые этапы

**Было:** первая ошибка параллельной подготовки могла запустить очистку раньше окончания соседних записей. При восстановлении существующий JSON мог быть заменён без проверки, не изменился ли он уже другим процессом. Ошибки очистки скрывались, а отдельного испытания промежуточных отказов не было.

**Стало:** сначала полностью готовятся новые тексты и исходные копии. Затем файлы устанавливаются последовательно. Перед установкой сверяются исходные данные, перед восстановлением — принадлежность нашей версии. Неудачное восстановление оставляет полную исходную копию с указанием пути. Ошибки очистки сообщаются. Реальные узлы целевого пути проверяются на символические ссылки.

**Почему:** обычный успешный запуск не доказывает сохранность данных при отказе диска или вмешательстве другого процесса.

Код: [`file-transaction.mts`](../src/core/file-transaction.mts), [`json-files.mts`](../src/core/json-files.mts). Подробные гарантии и пределы — в [`FILE_WRITES.md`](FILE_WRITES.md). Испытания используют настоящие временные файлы и управляемые сбои отдельных файловых операций.

### 7. Повторные HTTP-запросы соблюдают ограничения сервера

**Было:** `Retry-After: 120` сокращался до 30 секунд, после чего выполнялся преждевременный повтор. Незавершённое тело ошибочного ответа не отменялось явно, перенаправления не запрещались.

**Стало:** короткий интервал соблюдается точно; при ожидании больше 30 секунд запуск завершается с просьбой повторить позже. Ошибочный ответ отменяется до следующей попытки. Перенаправления запрещены, чтобы запрос с секретом не уходил на другой адрес.

**Почему:** `Retry-After` задаёт время до разрешённого повтора, а не пожелание к задержке. Это соответствует [документации Figma](https://developers.figma.com/docs/rest-api/rate-limits/#handling-rate-limited-requests).

Код: [`fetch-figma.mts`](../src/core/fetch-figma.mts). Тесты проверяют и количество запросов, и интервалы, и отмену ответа. Доступ к Variables API не используется и не проверялся.

### 8. Обновление проверочного слепка больше не портит предыдущий эталон

Вспомогательный инструмент раньше удалял старый каталог до проверки нового результата. Теперь новый слепок сначала собирается и проверяется отдельно, затем устанавливается с сохранением прежнего. Неправильная структура назначения, посторонние файлы, ссылки, пустой выбор и неполная проверка останавливают обновление.

Это исправление средства подготовки тестовых данных, не добавление обязанностей рабочему экшену. Создание раскладок в Figma по-прежнему находится вне его ответственности.

Код: [`update-full-fixture.mts`](../tools/update-full-fixture.mts). Сценарии отказов: [`update-full-fixture.test.mts`](../tests/update-full-fixture.test.mts).

### 9. Реализовано согласованное правило двух источников

**Было:** повтор ключа JSON останавливал экспорт, но ошибка не показывала оба исходных места. Разные ключи могли получить один `alias`, например при преобразовании имён `x1` и `x-1`.

**Стало:** отдельный реестр проверяет уже вычисленные имена каждого настоящего состояния. Ключ JSON и `web` уникальны во всей палитре, `figma` и `alias` — внутри её режима. При повторе ошибка указывает конфликтующее поле и значение, оба ключа и оба места в Figma: страницу, секцию, фрейм, состояние, а также идентификаторы узлов при их наличии. Совпадающие цвета разрешены; светлая и тёмная версии могут иметь одинаковый `alias`.

**Почему:** после преобразования у одного имени в коде не должно оказаться двух источников. Проверка не зависит от старого JSON, поэтому работает и для нового набора. Она выполняется до записи любого рассчитанного файла; при её ошибке экшен не доходит до экспортного коммита, отправки ветки и работы с запросом на слияние.

Режим теперь явно возвращается модулем палитры как служебное поле `mode`. Ядро не угадывает его по ключу JSON. Общая фабрика делает это автоматически; отдельное правило X5 сохраняет режим `static` и исходный путь стиля. В экспортируемом токене остаются прежние пять полей — `mode` туда не попадает. Проверка публичного объекта принимает только нужные ей `key` и `figma`, поэтому вспомогательные инструменты не обязаны выдумывать режим для готового JSON.

Код: [`token-sources.mts`](../src/core/token-sources.mts), [`parse-layout.mts`](../src/core/parse-layout.mts), [`_shared.mts`](../src/palettes/_shared.mts), [`token-contract.mts`](../src/core/token-contract.mts). Проверки: [`token-sources.test.mts`](../tests/token-sources.test.mts).

### 10. Порядок чтения и поведение при сбоях закреплены проверками

Порядок уже был правильным, поэтому код запуска не переписан: сначала один ответ Figma и список экспортных страниц, затем исходные JSON только выбранных наборов. Новые тесты проверяют, что повреждённый JSON отсутствующей страницы не читается синхронизатором, а повтор страницы обнаруживается до вызова загрузчика исходных JSON.

Отдельно проверено: конфликт во второй палитре не меняет первый файл и не создаёт другие; ошибка синхронизации не разрешает переходить к согласованию исчезнувших страниц и публикации. Подготовка служебной ветки по-прежнему выполняется до чтения Figma — это не экспортный коммит.

Вопрос об аварийном завершении снят как вопрос к дизайнеру. Рабочая папка уже изолирована в задании GitHub Actions. В документации прямо разграничены восстановление при перехваченной ошибке и жёсткая остановка процесса. Автоматическое восстановление после отключения питания не добавлялось и не обещается; для локального просмотра предусмотрен `--check` без записи.

Проверки: [`run-palettes.test.mts`](../tests/run-palettes.test.mts), [`action.test.mts`](../tests/action.test.mts). Пределы гарантий: [`FILE_WRITES.md`](FILE_WRITES.md).

## Что ещё проверить перед публикацией

1. **Живой источник.** Текущий полный слепок построен из нормализованных JSON, а не получен в этом запуске из Figma. Он доказывает совместимость результата, но не актуальность живой раскладки. Перед публикацией нужен проверочный REST-запуск на текущем Color Exporter.
2. **Реальное окружение GitHub.** Проверки выполнены локально на Node.js 24. Настоящий процесс на сервере GitHub с секретами и политиками организации в этой задаче не запускался.

Драфт подготовлен к предметному ревью: поведение можно проследить от входных данных до конкретных проверок и команд. Это не утверждение, что код больше никогда не потребует исправлений.

## Перенос в `ui-primitives`

Инструмент размещён в `scripts/color-exporter`, процесс — в `.github/workflows/export-colors.yml`. Корневой `package.json` получил отдельные команды проверки и локального запуска. Формулы, исходники ядра, модули палитр и эталонные JSON перенесены без изменений; документация команд адаптирована к запуску из корня репозитория.

При интеграции обнаружено, что релизный `utils/ci.sh` искал `styles/` в любой части пути. Вложенные тестовые JSON могли ошибочно вызвать выпуск пакета. Фильтр ограничен корневыми `icons/`, `styles/` и `animations/`. Семь новых проверок выполняют настоящий скрипт с подменёнными Git и npm: тестовые данные, включая удаления, не вызывают релиз; корневые ассеты по-прежнему вызывают ожидаемый тип выпуска.

В целевой структуре на Node.js 24 прошли установка по `package-lock.json`, проверка типов, общая сборка `scripts` и все 190 проверок экспортёра. Покрытие рабочего кода: 100% строк, 96,10% ветвей, 100% функций. Полный слепок десяти палитр воспроизводится побайтно. Живой REST-экспорт и ручной процесс на GitHub при переносе не запускались.

Состав зависимостей и файл их фиксации не менялись. При установке npm сообщил о 83 уязвимостях в существующем дереве зависимостей (21 умеренная, 47 высоких, 15 критических); обновление этих зависимостей находится вне данного переноса.
