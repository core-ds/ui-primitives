# Особые правила наборов

Страницы Figma определяют состав экспорта. Для `colors_<название_набора>.json` загрузчик ищет одноимённый модуль `<название_набора>.mjs` рядом с собой; исходник хранится как `<название_набора>.mts`. Подчёркивания в имени сохраняются. Если такого файла нет, действуют стандартные правила из [layout.mts](../layout.mts).

Каждый модуль экспортирует объект, проверенный через `satisfies Rule` из [contract.mts](../contract.mts).

| Поле | Назначение |
|---|---|
| `staticSlash` | Дополнительно разрешает статический префикс `static/` для X5; семейство и модификатор обрабатываются по общим правилам |
| `aliasNames` | Преобразование имён секции и фрейма только для расчёта `alias`; возвращает `undefined`, если к токену применяется общая формула |

Файл содержит только отличия алгоритма, а не перечень нынешних семейств или состояний. Новые семейства, токены, инверсия и состояния принимаются по общим правилам без правки модуля. Формулы цветов, ключей, `figma`, `web`, `alias`, порядок полей, сортировка и устаревание общие и не переопределяются. `aliasNames` меняет входные имена только для формулы `alias`; ключ, `figma` и `web` рассчитываются по исходной раскладке. Проверки структуры и состояний используют исходные имена; уникальность проверяется по окончательным выходным значениям, ошибки сохраняют исходный путь Figma. Сейчас преобразование задано только для [SuperApp](../../docs/palettes/superapp.md).

Новая стандартная страница не требует модуля. Удаление модуля не отключает оставшуюся страницу: она перейдёт на стандартные правила. Отключение выполняется удалением или переименованием страницы.
