# Контракт особого модуля палитры

Каждый обычный файл `*.mts` в этой папке — особые правила отдельного набора. Ядро обнаруживает файлы автоматически. Файлы с `_` в начале — служебные фабрики и не считаются наборами.

Стандартная страница `colors_<машинное_имя>.json` подключается без такого файла: `_create-standard.mts` создаёт её определение в памяти. Отдельный модуль нужен только для отличия от общего контракта.

## Почему у особого набора свой файл

От палитры зависят:

- экспортная страница единственного Color Exporter;
- имя целевого JSON;
- допустимые секции, фреймы и состояния;
- формула JSON-ключа;
- формулы `figma`, `web` и `alias`;
- допустимый состав настоящих состояний после общего игнорирования `empty`.

Эти правила нельзя переносить в ядро через условия по `id`. Иначе удаление одного набора или добавление другого потребует менять центральный алгоритм.

## Имя файла

Файл называется ровно `<id>.mts`. Например, модуль с `id: 'students'` обязан лежать в `students.mts`.

## Обязательные данные

Экспорт по умолчанию — объект с такими полями:

| Поле | Назначение |
|---|---|
| `id` | Уникальное имя для `--palette`; только строчные латинские буквы, цифры и дефис |
| `description` | Русское описание набора для человека |
| `figma.pageName` | Точное имя экспортной страницы |
| `targetJson` | Нормализованный относительный путь внутри репозитория |
| `stateNames` | Полный допустимый порядок состояний; `default` обязателен |

Имя страницы обязано совпадать с последней частью `targetJson`.

Порядок полей определения модуля произвольный; отсутствующие и лишние поля запрещены. Каталог может не содержать ни одного особого модуля: стандартные страницы всё равно обнаруживаются по ответу Figma.

## Обязательные функции

Обработчика `empty` в модуле нет. Общий парсер безусловно игнорирует прямоугольники с таким точным именем, не читая остальные свойства и не вызывая правила палитры. Дополнительное поле `isPlaceholder` запрещено проверкой контракта модуля.

### `validateSectionName(name)`

Проверяет имя секции. Функция не исправляет регистр, пробелы или опечатки.

### `validateFrameName(name)`

Проверяет имя фрейма токена. Новое имя, подходящее общей формуле, должно проходить без добавления в ручной список.

### `validateFrameComposition(context)`

Проверяет фрейм после обхода детей: допустимый состав настоящих состояний и исключения набора. Все `empty` к этому моменту уже проигнорированы; их количество не меняет решение. Ядро заранее требует хотя бы одно настоящее состояние, поэтому модуль не может разрешить пустой фрейм.

### `deriveIdentity(context)`

Возвращает ровно два поля:

```js
{
    key: 'dark_accent_primary_inverted',
    figma: 'accent_inverted/primary',
}
```

Общий помощник различает режим переменной `dark/accent`, который не входит в `figma`, и режим токена `static_accent`, который входит. Внутренние `/`, `_` и `-` пути сохраняются.

### `makeToken(context)`

Полностью создаёт активный объект:

```js
{
    rgba: 'rgba(...)',
    hex: '#...',
    figma: '...',
    web: '--color-...',
    alias: '...',
}
```

Ядро проверяет точный порядок, строковый тип, непустые значения и совпадение `figma` с идентификатором.

В `context.stateName` всегда передаётся настоящее состояние. Общие функции создания токена и `alias` требуют его явно и не угадывают по последнему сегменту пути.

## Виды правил

### Стандартная страница без модуля

`_create-standard.mts` выводит `id` и `targetJson` из имени страницы и применяет общие правила секций, состояний и `empty`. Исходный файл для конкретного набора не создаётся.

### Палитра только с `default`

Brand, Qualitative, Sequential, Monochrome, Students, Go и X5 используют `createDefaultOnlyPalette`. Файл набора передаёт фабрике свои правила:

```js
const definition = createDefaultOnlyPalette({
    id: 'example',
    label: 'Example',
    description: 'Описание набора',
    pageName: 'colors_example.json',
    sectionPattern: /^(?:light|dark)\/example$/,
});

export const deriveExampleIdentity = definition.deriveIdentity;
export const makeExampleToken = definition.makeToken;
export default definition.palette;
```

При необходимости можно передать отдельный `frameNamePattern` или русскую функцию `frameNameError`. Другой Figma-файл указать нельзя: источник зафиксирован в ядре.

### Палитра с особым составом состояний

BlueTint, Decorative и Promo объявляют объект явно и передают его в `definePalette`. Эта функция замораживает объект, настройки Figma и список состояний, чтобы их нельзя было случайно изменить после импорта. Правила состава фрейма остаются явными и не прячутся в фабрике с условиями.

## Стабильная сортировка

Модуль не управляет порядком JSON. Все наборы используют единственную сортировку из `core/stable-order.mts` по полному ключу. Индивидуальные функции сравнения запрещены.

## Добавление и удаление

- Подключить стандартный набор: добавить готовую страницу в единственный Color Exporter; JSON создаст экшен.
- Сделать правила особыми: добавить `<id>.mts`, проверки, `docs/palettes/<id>.md` и данные полного сценария.
- Отключить синхронизацию: убрать страницу; списка исключений нет.
- Вернуть: вернуть страницу с прежним именем.

Удаление особого модуля при оставшейся странице не отключает набор: на следующем запуске страница перейдёт на стандартные правила. Поэтому модуль удаляют отдельно только при осознанном переходе к общему контракту. Удаление опубликованного JSON остаётся отдельным решением вне экшена.

Подробный порядок находится в [`docs/ADD_OR_REMOVE_PALETTE.md`](../../docs/ADD_OR_REMOVE_PALETTE.md), полный расчёт полей — в [`docs/TOKEN_FIELDS.md`](../../docs/TOKEN_FIELDS.md), а правила действующих наборов — в [`docs/palettes/README.md`](../../docs/palettes/README.md).
