# Code Connect для иконок

Связи Figma с React-экспортами принадлежат UI Primitives вместе с исходными SVG и React-компонентами. Перенос связан с [PR core-components #2280](https://github.com/core-ds/core-components/pull/2280): компоненты потребляют вложенные примеры через общий контракт, а сведения о конкретных ассетах находятся здесь.

## Подтверждённое покрытие

Манифест содержит **1 480 корневых компонентов и наборов Figma**, **3 406 соответствий вариантов** и **3 354 уникальных React-экспорта**. Несколько Figma-компонентов могут ссылаться на один экспорт, поэтому эти числа обозначают разные единицы.

| --------------- | --------------------------: | ----------------: | ---------------------: |
| general (glyph) |                   696 / 696 |               669 |                    931 |
| glyph-26        |                   758 / 786 |               712 |                  2 355 |
| rocky           |                    40 / 146 |                38 |                     40 |
| ios             |                      0 / 36 |                 0 |                      0 |
| android         |                     16 / 36 |                 0 |                      0 |
| corp            |                     20 / 96 |                20 |                     21 |

| site            |                     22 / 62 |                22 |                     22 |

Это подтверждённая часть опубликованной Figma-библиотеки, а не весь SVG-каталог UI Primitives. Из индекса **1 886 корней** прочитаны **1 572**. Ещё **314** не прочитаны после достижения квоты MCP; 18 неуспешных пакетов чтения согласованы с этими идентификаторами. Непрочитанные корни не считаются ни подходящими, ни неподходящими для Code Connect.

Размер, семейство и выбранный вариант сохраняются. В частности, есть настоящие 32px-варианты и цветные ассеты; универсального ограничения 20/24px или `Color=False` нет. Правила выбора, миграции, замены иконок и темы приложения не участвуют в сопоставлении.

Пять первоначальных ручных шаблонов и их идентификаторы сохранены. Префикс `core-` в этих идентификаторах обеспечивает совместимость ранее опубликованных связей и не обозначает владельца файлов. Остальные 1 475 шаблонов генерируются в `generated/`; GitHub помечает только этот каталог как сгенерированный.

## Источники и точное сопоставление

[`manifest.json`](manifest.json) хранит проверенные соответствия и происхождение данных:

- **Figma:** реальные node-id и component key, свойства набора, идентификатор варианта и явный `[asset_identifier]` из его исходного описания. Новые привязки создаются только для корней со статусом `CURRENT`.
- **UI Primitives:** точные `middle`, `web` и `webComponent` из `icons-demo/src/shared/config/meta_<pack>.json`, соответствующие SVG и React TSX этого репозитория.
- **Хаб:** справочник glyph-26 использован для сверки имён и экспортов. Все его 2 164 записи совпали с текущими UI-метаданными; в UI есть ещё 232 записи. Манифест хаба не содержит индивидуальных Figma node-id и не используется для их вычисления.

Связь строится так:

```text
подтверждённая Figma-страница → пакет
конкретный вариант → один явный asset tag
точное совпадение tag с meta.middle → meta.web/webComponent
SVG и React TSX → проверка размера с Figma
```

Регистр, дефисы, подчёркивания, стиль и размер в именах не исправляются. Значения свойств разбираются по фактическим `componentPropertyDefinitions` и имени варианта Figma, а не выводятся из SVG-имени. Дублирующиеся или неоднозначные состояния не принимаются. В манифест попадает необходимая информация для привязки, а не полное дерево Figma-файла.

### Что остаётся без привязки

Для **406 корней** из индекса пока нет готовой связи: 314 не прочитаны, 42 не опубликованы, у одного есть неопубликованные изменения, а у 49 прочитанных опубликованных корней не найдено ни одного подтверждённого варианта.

`coverage` отдельно сохраняет причины на уровне вариантов: у **2 504 вариантов** нет явного asset tag; у 33 tag не найден в UI-метаданных; у семи не подходит геометрия. Для 16 прочитанных Android-вариантов метаданные не объявляют Web-экспорт.

Это категории разных уровней; причины вариантов могут относиться к тем же 49 корням без поддержанного содержимого. Их нельзя складывать как число исключённых иконок. Для каждого случая сохранены root/variant ID и конкретная причина. Неподдержанные состояния записаны в `unsupported` и завершаются явной ошибкой шаблона. Вариант, отсутствующий в опубликованном наборе, отличается от варианта без подтверждённого UI-экспорта.

Наборы `classic`, `shape`, `art` и `dev` находятся за пределами использованного каталога метаданных. Их наличие среди SVG не считается доказательством готовой Figma-связи.

## Проверка

После установки зависимостей из корня репозитория:

```sh
pnpm figma:connect:check
```

Проверка не требует PAT и ничего не публикует. Она проверяет воспроизводимость сгенерированных файлов, TypeScript и официальный parse всех шаблонов, свойства и явные отказы, размеры SVG и React-компонентов, импорты, source identity и метаданные. JSX проверяется против текущих `packages/<pack>/src` с типами этого workspace. Совместимость с конкретной опубликованной npm-версией и визуальная эквивалентность не заявляются.

Отдельные регрессии обнаруживают неоднозначный разбор вариантов, нормализацию asset tag, подмену пакета или размера, потерю импорта и попытку признать неполный Figma-снимок полным.

Шаблон возвращает SVG-компонент без адаптирующей обёртки. Потребитель получает `metadata.props.svgSize` и `metadata.props.imports`, использует их для своего слота и передаёт импорты через каждый уровень вложенности.

## Обновление каталога

Канонические данные находятся в `manifest.json`. `generated/*.figma.ts` и списки `include` воспроизводятся из него:

```sh
pnpm figma:connect:generate
pnpm figma:connect:generate --check
```

Для расширения сначала получают новое чтение Figma с фактическими identity, definitions и asset tags. Скрипт `catalog.cjs` принимает это чтение отдельно от полного индекса корней и сверяет недостающие ID с ошибками чтения:

```sh
node scripts/code-connect/catalog.cjs \
  --capture /path/to/figma-capture.json \
  --inventory /path/to/figma-inventory.json \
  --hub-catalog /path/to/assets_glyph-26.json \
  --write
pnpm figma:connect:generate
pnpm figma:connect:check
```

`--hub-catalog` необязателен и служит сверке источников. CI и готовые шаблоны не обращаются к соседнему клону хаба. Исходный снимок Figma остаётся вне репозитория; в манифесте сохраняются время получения, digest снимка и данные конкретных соответствий. Ручные пять шаблонов не перезаписываются генератором. Изменение их поведения требует отдельной явной правки.

## Публикация

Публикация выполняется вручную после проверки и согласования с владельцем библиотеки:

```sh
pnpm figma:connect:publish --dry-run
pnpm figma:connect:publish
```

CLI читает `FIGMA_ACCESS_TOKEN` из окружения. Токен не хранится в репозитории и не нужен в PR-проверках. Команда использует только явный список канонического `figma.config.json`.

Добавление файлов в Git само по себе не обновляет опубликованные Figma-связи. Следующая публикация из UI Primitives обновит их данные, включая `source`; её результат требуется подтвердить ответом CLI и чтением через MCP. Расширение каталога в этом PR не означает, что новые связи уже опубликованы.
