# Code Connect для иконок

Пять наборов опубликованной Figma-библиотеки Icons связаны с React-экспортами этого репозитория. Перенос связан с [PR core-components #2280](https://github.com/core-ds/core-components/pull/2280): компоненты потребляют вложенные примеры, а сведения о конкретных иконках принадлежат UI Primitives.

## Состав

| Набор Figma       | Пакет                     | Поддержанные варианты                  |
| ----------------- | ------------------------- | -------------------------------------- |
| ArrowLeft         | `@alfalab/icons-glyph-26` | Default 20/24, Line 20/24, Thinline 20 |
| InformationCircle | `@alfalab/icons-glyph-26` | Default 20/24, Line 20/24, Thinline 20 |
| ChevronDown       | `@alfalab/icons-glyph-26` | Default 24, Line 20/24, Thinline 20    |
| DotsThreeVertical | `@alfalab/icons-glyph`    | s 16, m 24                             |
| Diamonds          | `@alfalab/icons-glyph`    | s 16, m 24, xxl 48                     |

Это 19 соответствий пяти наборов, а не подключение всего каталога. Исходный набор, стиль и размер сохраняются. Неподдержанные состояния отклоняются явно; одноимённая иконка другого семейства не подставляется.

`manifest.json` перечисляет Figma root, свойства и варианты, SVG, React-экспорт и размер. `.figma.ts` исполняет сопоставление в Code Connect. Идентификаторы и Figma URL сохранены при переносе; `source` указывает на React-исходники UI Primitives. Префикс `core-` в существующих идентификаторах сохранён для совместимости и не обозначает владельца файлов.

## Проверка

Из корня репозитория:

```sh
pnpm figma:connect:check
```

Проверка не требует PAT и ничего не публикует. Она выполняет TypeScript и официальный parse пяти шаблонов, проверяет все заявленные состояния и отказы, размеры SVG и локальных React-компонентов, импорты и метаданные. Сгенерированный JSX проверяется против `packages/glyph/src` и `packages/glyph-26/src` с типами текущего workspace. Это проверка workspace API; совместимость с конкретной опубликованной npm-версией и визуальное соответствие не заявляются. Отрицательные контроли обнаруживают подмену семейства, размера и потерю импортов.

Шаблон возвращает SVG-компонент без обёртки адаптации. Потребитель получает `metadata.props.svgSize` и `metadata.props.imports`; он использует эти поля для своего слота и передаёт импорты через каждый уровень вложенности. Информация о теме приложения или правилах миграции ассетов не входит в связь.

## Добавление набора

1. Установить исходный опубликованный component set в Figma и все его свойства.
2. Подтвердить точные соответствия его вариантов SVG и React-экспортам этого репозитория. Отдельно перечислить неподдержанные состояния.
3. Добавить `.figma.ts` и запись в `manifest.json`; включить шаблон в `figma.config.json` и `tsconfig.code-connect.json`.
4. Запустить проверку, затем отдельно выполнить серверную проверку и согласованную публикацию.

## Публикация

Публикация выполняется вручную после проверки и согласования с владельцем библиотеки:

```sh
pnpm figma:connect:publish --dry-run
pnpm figma:connect:publish
```

CLI читает `FIGMA_ACCESS_TOKEN` из окружения. Токен не хранится в репозитории и не нужен в PR-проверках. Команда использует только пять файлов канонического `figma.config.json`.

Перенос файлов в Git сам по себе не обновляет и не снимает уже опубликованные Figma-связи. Следующая публикация из этого репозитория обновит их данные, включая `source`; её результат нужно подтвердить ответом CLI и чтением через MCP.
